# Verification

Verified locally on 2026-09-29 with Python 3.12 and Node.js 22 / Chrome.

- Backend: 31 Python unittest tests passed. Coverage includes default denial,
  independent opt-in/revocation for all five mounts, malformed options, Markdown
  round trips, backups with mode/owner preservation, traversal and symlink/hardlink
  rejection, binary and Unicode uploads, conflicts, size limits, Ingress checks,
  same-origin request headers and mocked Home Assistant API contracts. Added
  creation conflicts/validation, config prechecks before restart/reload, fixed
  upstream endpoints, concurrent action rejection,
  malformed responses, denied/missing credentials and timeout/no-retry behavior.
- Frontend: TypeScript checking and Vite production build passed.
- Browser: 21 Playwright tests passed against the production build and an isolated
  Flask fixture server. Tested Markdown rendering/saving/persistence, picker and
  drop uploads, root switching, unsaved edits, preview sanitization, YAML/JSON
  validation, history isolation, save errors and 320/768/1024px responsive layouts.
  Added top-toolbar creation, dirty-document guards, manual validation, confirmed
  restart/cancel, reload/error details, entity refresh/failure and dropdown keyboard
  navigation with empty values, automatic suggestions, substrings and Korean names.
- The desktop happy-path browser test recorded no JavaScript or console errors.
- `npm audit`: zero known vulnerabilities after updating the transitive `nanoid`
  dependency in the lockfile.
- Parsed `config.yaml` and both translations; checked mounts, opt-in defaults,
  schema keys, absence of host ports and translation coverage. Checked 0.2.0 API
  permissions (`homeassistant_api`, `hassio_api`, `hassio_role: homeassistant`)
  without full access or Docker API access. `sh -n` passed.
- Inspected desktop and mobile screenshots generated by the browser tests.

## 0.3.0 explorer and entity translations

- Recursive copy/rename/delete, cross-root opt-in permissions, source preservation
  on failure, simulated cross-device moves, no-overwrite conflicts, protected roots,
  descendant/traversal/link rejection passed backend tests.
- Fixed Core template requests produce state_translated fields; failed translation
  requests retain raw states. Browser dropdown tests verify translated display.
- Unified roots, creation/upload target selection, context menus, dirty-document
  protection, moved-file save destinations, keyboard clipboard/menu/arrow navigation,
  and mobile menu bounds were checked in Chrome. HA controls remain available on mobile.
- Production build and extracted 0.3.0 archive build passed using local dependencies.
  The archive contains file_actions.py and all frontend source modules.

## 0.2.1 packaging

0.2.1 packaging verification: generated the local-app archive, extracted it into
a temporary directory, and compared all 10 TypeScript sources byte-for-byte with
the workspace. The extracted frontend passed TypeScript/Vite production build
using the existing local dependency installation. Required hidden build files
were present; node_modules and browser-test artifacts were absent. This checks
archive completeness, not an aarch64 Docker build.

## Not verified in this environment

Docker is unavailable, so the multi-stage container build and amd64/aarch64 image
execution were not run. No Home Assistant Supervisor instance is connected;
actual installation, mounts, authenticated Ingress, live entity discovery and
live Core validation/reload/restart still require a Home Assistant smoke test. The automated
HA API tests use mocks and do not establish live integration success.

## Upstream fixes made during verification

- Filenames and paths are escaped before inserting tree HTML.
- File switches reset editor undo history; skipping history recording alone was
  insufficient and could insert previous-file content into another document.
- File loading and saving protect editor state against concurrent navigation.
- Save failures retain a visible error and keep the unsaved document available.
- Production startup enforces Ingress even if the supervisor token is missing.

failure traces are generated under `codemirror/frontend/test-results/` (ignored).
